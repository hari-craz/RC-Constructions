# Form, domain, email and security.txt (`docs/FORM-AND-DOMAIN.md`)

Nothing here has been changed on Formspree, Vercel, DNS or GitHub. These are the steps for the site owner. Dashboard menu names change over time; where a label may differ, the intent is given.

## 1. The enquiry form (Formspree)

### How it is wired

- `src/sections/Contact/Contact.tsx` posts to `https://formspree.io/f/<VITE_FORMSPREE_ID>` with `Accept: application/json` and a JSON body (verified in the source; the success and error handling depends on that header). A hidden `_gotcha` field is the spam trap.
- `VITE_FORMSPREE_ID` is read **at build time** (Vite inlines it). Setting it in Vercel has no effect until the site is rebuilt and redeployed.
- If the ID is missing, the button is disabled and the page says "Sending is switched off until the form ID is set." On error the page shows the phone number and email address as a fallback.

### What the live review found (2026-10-16)

On `https://rc.unitaryx.org` the send button is disabled: the ID was not set when that build ran, so no Formspree request is made and there are no 403s from the form. See `docs/LIVE-REVIEW-phase-13.md`.

### Steps to check and fix (you, in the dashboards)

1. **Vercel**: Project, Settings, Environment Variables. Add `VITE_FORMSPREE_ID` with the form's 8-character ID for the **Production** environment. Then Deployments, redeploy the latest production deployment (a new build is required).
2. **Confirm the ID reached the build**: `curl -s https://rc.unitaryx.org/ | grep -o 'assets/main-[^"]*\.js'`, then `curl -s https://rc.unitaryx.org/<that path> | grep -c '<YOUR_FORM_ID>'` should print 1 or more. Also open the site: the Send enquiry button should be amber, not outlined.
3. **Formspree, the form**: open the form named for RC Constructions.
   - **Recipient**: confirm the notification email is the company's address, and that Formspree shows it as verified (it sends a verification email once).
   - **Allowed domains / origin restriction** (under the form's settings; on some plans this is called domain restriction or "Restrict to domain"): add exactly the production host, `rc.unitaryx.org` (and the final domain when it changes, plus `www.` if used). A missing or different domain returns **403** to browser submissions. If you test from `localhost`, add it temporarily or use a separate test form.
   - **Plan limits and archived forms**: an archived, deleted or over-limit form also answers with an error; check the form's status and the monthly submission count.
   - **Spam filtering**: leave the honeypot field `_gotcha` enabled.
4. **Test from the owner's side only** (the site must never be tested with a real enquiry by anyone else): submit the live form once yourself with an obviously fake name such as "Test, please ignore", confirm the email arrives, then delete the submission in Formspree.
5. **Check the error path**: in a private window, block `formspree.io` (browser dev tools, Network, block request domain), submit the form, and confirm the page shows the phone number and email address.

### Formspree notifications and the company domain

Formspree sends the notification email from its own systems to the registered recipient address. It is not sent from the company's domain, so SPF, DKIM and DMARC for the company domain do not cover those notifications. They matter for the company's own mail (section 3).

## 2. Domain and DNS

### One canonical URL

The canonical URL lives in one place: `src/config/site.json` (`siteUrl`). The build uses it for the `<link rel="canonical">`, `og:url`, `og:image`, `twitter:image` and JSON-LD URLs in `index.html`, the privacy and terms pages, `robots.txt`, `sitemap.xml` and `security.txt` (generated by `vite.config.ts`, see `src/lib/siteFiles.ts`). To change domain, edit that file only, plus one literal that cannot read it: the `Access-Control-Allow-Origin` value in `vercel.json` (a test fails if they differ). Then run `node scripts/check-live.mjs`.

### Records on Vercel

In Vercel: Project, Settings, Domains, add the final domain. Vercel then shows the exact records for that project; use the values it shows. The usual shapes are:

| Host                                 | Type  | Value                                                         |
| ------------------------------------ | ----- | ------------------------------------------------------------- |
| apex (`example.com`)                 | A     | `76.76.21.21` (or the project-specific address Vercel shows)  |
| `www`                                | CNAME | `cname.vercel-dns.com` (or the project-specific target shown) |
| a subdomain such as `rc.example.com` | CNAME | `cname.vercel-dns.com` (or the project-specific target shown) |

Choose one of apex or `www` as the canonical host and set the other to redirect to it in Vercel (Domains, edit, Redirect to). Keep `siteUrl` equal to the canonical host. Remove old A, AAAA or CNAME records on the same host that point elsewhere.

### Verify

```bash
dig +short A example.com
dig +short CNAME www.example.com
curl -sI https://example.com/ | head -20          # 200, HSTS, security headers
curl -sI http://example.com/ | head -5            # redirects to https
curl -sI https://www.example.com/ | head -5       # redirects to the canonical host
node scripts/check-live.mjs https://example.com   # headers, canonical consistency, security.txt, console
```

### HTTPS and HSTS

Vercel issues and renews the certificate once DNS points at it. The site sends `Strict-Transport-Security: max-age=63072000; includeSubDomains` (without `preload`; the live review found `preload` while the final domain was not settled). Add `; preload` and submit the domain at hstspreload.org only when the final domain is fixed and every subdomain you use serves HTTPS, because removal from the preload list is slow. Change it in both `vercel.json` and `nginx.conf` (`pnpm compare:headers` checks they match).

### CORS

A static site does not need CORS headers for its own pages. The live review found `Access-Control-Allow-Origin: *` on every response; it is not in `vercel.json` or `nginx.conf`: Vercel adds it to static deployments by default. `vercel.json` now sets `Access-Control-Allow-Origin` to the site's own origin, which replaces the default. After deploying, confirm: `curl -sI https://rc.unitaryx.org/ | grep -i access-control` shows the site origin, not `*`. If it still shows `*`, the value comes from a Vercel setting outside the repo: in the project's Settings, Headers (or the team's Firewall and Edge rules), delete any rule that sets `Access-Control-Allow-Origin`.

## 3. Email domain trust (SPF, DKIM, DMARC)

First question for the company: **which mail provider does the company use?** The records differ. The values below show the shape; the provider's console issues the real ones. Nothing has been changed.

### Google Workspace

| Purpose | Host                | Type | Value                                                                                                                                        |
| ------- | ------------------- | ---- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| SPF     | `@` (the apex)      | TXT  | `v=spf1 include:_spf.google.com ~all`                                                                                                        |
| DKIM    | `google._domainkey` | TXT  | the long key Google shows (Admin console, Apps, Google Workspace, Gmail, Authenticate email, Generate new record, then Start authentication) |
| DMARC   | `_dmarc`            | TXT  | `v=DMARC1; p=none; rua=mailto:dmarc@example.com; fo=1`                                                                                       |

### Zoho Mail

| Purpose | Host                    | Type | Value                                                                                                                              |
| ------- | ----------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------------------- |
| SPF     | `@`                     | TXT  | `v=spf1 include:zoho.in ~all` for the India data centre (`zoho.com` for the US one; use the one shown in Zoho's Domains, SPF page) |
| DKIM    | `<selector>._domainkey` | TXT  | the key Zoho shows (Mail Admin, Domains, DKIM; the selector is often `zmail`)                                                      |
| DMARC   | `_dmarc`                | TXT  | `v=DMARC1; p=none; rua=mailto:dmarc@example.com; fo=1`                                                                             |

Only one SPF record may exist per host; if the company sends from several services, merge them into one `v=spf1 ... ~all` line. Start DMARC at `p=none`, read the reports for a few weeks, then move to `p=quarantine`.

### Verify

```bash
dig +short TXT example.com                      # contains v=spf1 ...
dig +short TXT google._domainkey.example.com    # Google DKIM (use zmail._domainkey for Zoho)
dig +short TXT _dmarc.example.com               # v=DMARC1; ...
```

Then send a message to a Gmail account, open "Show original" and confirm SPF, DKIM and DMARC all say PASS.

## 4. security.txt

`/.well-known/security.txt` follows RFC 9116: `Contact` (a `mailto:` for the security or general address, from `src/content/company.ts`), `Expires`, `Preferred-Languages`, `Canonical`. `Expires` is regenerated on every build, 330 days ahead, so it only lapses if the site is not redeployed for 330 days. CI runs `pnpm check:security-txt` against `dist/` (it must be more than 30 days ahead) and `scripts/check-live.mjs` checks the live file. Set a yearly reminder to redeploy, or add a Vercel deploy hook on a schedule.

## 5. What the live review found about WASM and 403 errors

On a clean browser profile at desktop and mobile there were no WebAssembly errors and no 403 responses (`docs/LIVE-REVIEW-phase-13.md`). The bundle contains no WebAssembly and the CSP does not allow it (no `wasm-unsafe-eval`; adding it was not needed and was not done). If a reviewer still sees them, the likely sources are a browser extension or the Vercel preview toolbar; test in a fresh private window with extensions disabled. The one real 404 was the missing founder portrait file, now handled by the `portraitAvailable` flag.

The notice and terms (`src/legal/privacy.ts`, `src/legal/terms.ts`, marked `REVIEW BY COMPANY ADVISER`) state only what the code and the providers' published documents support. These points were left out because they could not be verified:

1. How India's Digital Personal Data Protection Act, 2023 applies to this business and to this form, including whether and when any duty (notice, consent wording, children's data, breach reporting) applies, and whether the notice should name a grievance contact.
2. Which regulator or board a visitor may complain to, and the correct wording for that.
3. The retention period (a sample is in `company.ts`).
4. Whether sending form data to Formspree (United States and other countries) needs additional wording about transfers.
5. The governing law and courts line for the terms, and the limits of the liability clause.
6. Whether an accessibility statement is wanted (it was not added: no audit beyond automated checks supports one).
